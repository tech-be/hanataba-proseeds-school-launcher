# ＜区分名＞ — 機能の差分

> **これはひな形です。** `00-template/` ごと `NN-<区分名>/` にコピーし、[breakdown.md](breakdown.md) / [review.md](review.md) / [migration-spec.md](migration-spec.md) と併せて使ってください。**このディレクトリは区分ではないので、README の区分一覧にも集計にも含めません。**

この区分のデータを**使う機能**を1つずつ挙げ、新旧でどう違うかを書く。

[移行の原則](review.md#移行の原則)の1で「新環境にその機能が無いことは移行しない理由にならない。**データは移し、機能は別途用意する**」と決めた。この文書は、その「機能は別途用意する」側で**何が要るか**を洗い出すためのもの。

- [review.md](review.md) は「**データをどこへ入れるか**」、この文書は「**入れたデータを誰がどう使うか**」
- 機能の有無の出発点は、運営と共有している「既存機能と新システムの保有」（データ種95件ごとの ◯ / X）。**データ種の列で対応を追えるようにする**
- **データが移っていても、機能が読んでいなければ効かない。** 受け皿を足した列は、新の機能が読んでいるかまで確かめて書く

## 書くときの約束

- **1機能 = 1つの `###` 見出し。** ID は `F01` から振り、下の「機能の一覧」の行と**順序を揃える**
- **機能は利用者から見える単位で切る**（「ログイン」「テスト受験」「領収書の発行」）。テーブル単位では切らない
- **根拠の場所を必ず書く。** 旧は PHP のファイルとメソッド、新は API のルート・Go のファイルと関数・画面の URL。推測で書かない
- **「内容」は違いだけ、「対応」はどうするかだけ**を書き、同じことを二度書かない（[review.md](review.md) と同じ）

### 判定（機能ごとに1つ）

| 判定 | 意味 |
|---|---|
| **◯ 同等** | 新にもあり、利用者から見て同じように使える。差分の表は空か「低」だけ |
| **△ 差分あり** | 新にもあるが、参照するデータ・振る舞い・権限のどれかが違う |
| **X 新に無い** | 新に機能が無い。データだけ移っている状態になる |
| **新のみ** | 旧に無く新にだけある。移したデータがその機能でどう見えるかを書く |

### 差分の種類

| 種類 | 何を書くか |
|---|---|
| **機能** | 機能そのものの有無、または一部だけある（例: 講座単位の修了証はあるが商品単位は無い） |
| **参照データ** | **移すが新が読まない列**、**新が読むが旧に無い列**、読む列が違う（例: ログインの ID がメールアドレスに変わる） |
| **振る舞い** | 判定条件・計算・並び順・状態の遷移が違う |
| **権限** | 使えるロールが違う |
| **画面** | 見え方だけの違い（データの意味は変わらない） |

### 深刻度

| 深刻度 | 基準 |
|---|---|
| **高** | 旧でできていたことが**できなくなる**、または旧で止めていたことが**できてしまう**（無効の会員がログインできる、など） |
| **中** | できることは同じだが、**結果や手順が変わる**（判定の条件、計算、並び順） |
| **低** | 見え方だけ、または利用者が気づかない |

### 対応の書き方

**動詞で始め、誰が何をすれば閉じるかが分かる粒度にする。**

| 型 | 書き出しの例 |
|---|---|
| 新で実装する | `新で…を実装する（…を読む）` |
| 運用で代替する | `運用で代替する。＜誰が何をするか＞` |
| 受け入れる | `対応不要。＜なぜ許容できるか＞` |
| 運営に確認する | `運営に…を確認する`（[open-questions.md](../open-questions.md) に載せる） |
| **まだ決まっていない** | `未決: ＜決めること＞` |

**未決の件数が、そのまま切り替え前に閉じるべき論点の数になる。**

## 各機能

### 書き方

````markdown
### F01 ログイン

利用者: 受講者・管理者 ／ データ種: B02 ロール、B03 メールログイン、B04 login_id ログイン、B05 パスワード ／ 判定: **△ 差分あり**

- 旧: `application/models/AuthModel.class.php` の `login()` / `_findUserMainByLoginIdAndPassword()`
- 新: `POST /api/v1/auth/login` → `btoc-backend/internal/service/auth_service.go` の `Login` ／ 画面 `https://<slug>.<ドメイン>/login`

#### 参照データ

移した列ごとに、**旧で使っていたか / 新で読んでいるか**を書く。

| データ | 旧（テーブル.列） | 新（テーブル.列） | 旧で使う | 新で使う | 差分 |
|---|---|---|:--:|:--:|---|
| ログイン ID | `user.login_id` | `users.login_id` | ◯ | — | 新はメールアドレスでログインする |
| メールアドレス | `user.mail_add` | `users.email` | — | ◯ | 旧はログインに使っていない |
| 有効フラグ | `user.valid_chk` | `users.is_valid` | ◯ | — | 新は読まない（`status` だけを見る） |
| ログイン期間 | `user.entry_date` / `user.limit_date` | `users.login_start_date` / `users.login_end_date` | ◯ | — | 新は読まない |
| ロックアウト | `user.is_lockout` | `users.is_lockout` | ◯ | — | 新は読まない |

#### 差分

| 種類 | 深刻度 | 内容 | 対応 |
|---|:--:|---|---|
| 参照データ | 高 | 旧は `login_id` でログインし、新はメールアドレスでログインする。会員が入力するものが変わる | 未決: 新でログイン ID でもログインできるようにするか、メールアドレスに切り替えると会員に案内するかを決める |
| 振る舞い | 高 | 新は `status = 'active'` とパスワードしか見ない。旧でログイン期間外・ロックアウト中だった会員もログインできる | 新でログイン時に `is_valid` / `login_start_date` / `login_end_date` / `is_lockout` を読む |
| 機能 | 中 | 旧にあった同時接続数の制限（`login_limit_count`）が新に無い | 未決: 運営に使っているかを確認する |
| 権限 | 中 | 新が扱うロールは4つだけ。旧の運営管理者・グループ管理者などは、ログインできても権限が想定どおりにならない | 未決: 旧ロールの扱いを決める |
````

### 移さないデータがある区分の参照データ

データを移さない区分（06 対象外）では、参照データの表を次の形にする。**次の3つを確かめるため。**

- **不要なデータを移していないか**（「移行」が「移す」なのに、新で使わないもの）
- **新に受け皿のテーブルがあるのに、対象外にしていないか**（「新の受け皿」がある行）
- **新に同等の機能があるのに、対象外にしていないか**（「新の同等の機能」が ◯ / △ の行）

````markdown
| データ | 旧（テーブル.列） | 旧で使う | ステージング | 移行 | 新の受け皿 | 新の同等の機能 | 判断 |
|---|---|:--:|---:|---|---|---|---|
| リンク | `link` | ◯ | 3 | 移さない | `library_materials`（`kind = 'url'`） | ◯ ライブラリ | **要確認**: 受け皿も同等の機能もある |
````

「判断」は **対象外で妥当** か **要確認**（理由つき）で書き、要確認のものは冒頭の「3つの確認の結果」にまとめる。**「使っていない」を対象外の根拠にしているものは、件数を数えて前提が崩れていないかも確かめる。**

## 移したが新で読まれないデータ

各機能の「参照データ」の表で**新で使う が `—`** の行を、この区分の分だけ集めたもの。**受け皿を足したのに、どの機能も読んでいない**ものがここに並ぶ。

| 新テーブル.列 | 旧 | 旧で使っていた機能 | 対応 |
|---|---|---|---|
| `＜テーブル＞.＜列＞` | `＜旧テーブル＞.＜列＞` | F＜nn＞ ＜機能名＞ | ＜差分の表の対応と同じもの＞ |

> **ここに載るのは「移し損ね」ではない。** データは移っているので、機能の側を直せば効くようになる。逆に、ここに載ったまま切り替えると、旧で効いていた制限や表示が**黙って消える**。

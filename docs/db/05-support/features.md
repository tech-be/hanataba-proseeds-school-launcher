# サポート機能 — 機能の差分

サポート機能のデータ（LINE・クーポン・お知らせ・メール・問い合わせ・ファイル・就業支援・コミュニティ・利用料の集計）を**使う機能**を1つずつ挙げ、新旧でどう違うかを書く。
書き方の約束（判定・差分の種類・深刻度・対応の書き方）は [ひな形](../00-template/features.md) を参照。

- **調査時点:** 2026-09-30
  - 旧: `learningware-kiracari`
  - 新: `school-launcher` の `feat/lw2-billing-schema`（`hanataba_dev` とアプリのコードは同じ）。就業支援は別サービスの `career-backend`
- **根拠の場所の書き方:**
  - 旧は `learningware-kiracari/application/` からの相対パス。
  - 新は `btoc-backend/internal/` / `career-backend/internal/` / `btoc-frontend/src/` からのパス。
- **05 は移行ツールの実装が一部だけ**（ファイル・ライブラリのみ）。各機能に「移行ツール」の状態を書く。未実装の機能は「新の受け皿を新の機能が使っているか」までを見る

> **要点。** 05 は、旧にあって新に無い機能が多い（Web プッシュ・個別メッセージ・スカウト・ポートフォリオ）。新にある機能も、作りが旧と違うものが多い。
>
> - **問い合わせ**は、旧は何往復でもやり取りでき、ファイルも添付できた。新は質問と回答が1つずつで、添付が無い（F06）
> - **求人**は、旧は求人企業の会員が自分で出し、応募に返信した。新は管理者だけが登録する（F09）
> - **クーポン**は、新は Stripe のクーポンが要る。旧のクーポンをそのまま入れても、Stripe の決済では割引されない（F02）
>
> **ファイルの移行に要る2表（F08）は、2026-09-30 に school-launcher（`20260930052453`）に足した。** あわせて、どの区分にも仕分けていなかった旧テーブルのうち、助言メモ・フォロー・コミュニティの分類・利用料の集計を 05 で移すようにした（F10〜F13）。

## 各機能

### F01 LINE 連携

利用者: 受講者・管理者 ／ データ種: U06 LINE 連携・配信 ／ 判定: **△ 差分あり** ／ 移行ツール: 会員の LINE の紐付けは基盤で移す。配信の本文・履歴は未実装

- 旧: 設定は `modules/admin/controllers/ConfigLineController.php`、LINE での登録・紐付けは `LoginController::lineEntryAction()` / `lineAlignAction()`、配信は `models/SendLineModel.class.php` と `batch/LineSendBatch.class.php`（お知らせ・求人・フォローメール・自動メールごとに LINE の本文を書ける）
- 新: `line/*`（紐付け・友だち状態・送信の記録）、LINE でのログインは `handler/oauth_line_handler.go`。送れるのは決まった通知の写しとお知らせだけ

#### 差分

| 種類 | 深刻度 | 内容 | 対応 |
|---|:--:|---|---|
| 機能 | 中 | 旧は管理者がお知らせ・求人・フォローメール・自動メールごとに、LINE 用の本文を書いて送れた。新は決まった通知をそのまま写して送るだけで、本文を書く画面が無い | 未決: 運営に、LINE の本文を個別に書く必要があるかを確認する（[E43](../open-questions.md#e-切り替え後の機能で決めておきたいこと)） |

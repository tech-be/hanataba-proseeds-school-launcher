### 2026-10-27 の追加の確認（コースのキャンセル・返金・申し込み、ライブのキャンセル・予約）

移したデータの上で、新アプリの API を実際に操作し、前後の DB の行を確かめた（確認用の DB。32 項目すべて OK）。

| 処理 | 結果 |
|---|---|
| コースのキャンセル（運営の割り当ての取り消し） | 移した割り当てを取り消すと、コースの受講が `revoked`、講座の受講登録が `expired` になり、講座を開けなくなる（200 → 403）。もう一度取り消すと 400。直接付与の元の状態に戻す処理は、ステージングに「元の状態が受講中」が 0 件で確かめていない |
| 返金 | 移した決済の返金は 500 で、決済・コースの受講・返金の行は変わらない（新は Stripe しか呼ばない。確認事項 D23） |
| 新しいコースの申し込み | 無料のコースに申し込める（コースの受講と講座の受講登録ができ、講座を開ける。もう一度は 409）。有料のコースに振込で申し込み、運営が入金を確認すると購入・受講中になる。振込の確認の一覧には移した決済は出ない。移したコースの受講が有効なコースには申し込めない（409） |
| ライブの予約・キャンセル（チケット不要） | 移した開催回を予約でき、自分の予約に出る。同じ回は 409。キャンセルで席が戻り、もう一度予約できる |
| ライブの予約・キャンセル（チケット） | 移した残高は期限切れで予約できない（409。旧と同じ）。運営が付与したチケットで予約すると 1 枚引かれ、期限内にキャンセルすると戻る（T-09 を直したあと）。期限を過ぎた回のキャンセルは 409 |

新システムの作りで気づいたこと（移行の範囲の外）: ライブの予約は講座の受講登録の行があるかだけを見て、期限は見ない（期限切れの受講登録の会員でも予約できた）。旧は受講権限の期間を見ていた。

# 対象外 — 機能の差分

**移行しないと決めたデータ**（[内訳](breakdown.md) の X01〜X05 と、決定で対象外にしたバッジ）を使っていた機能を挙げ、新で何が起きるかを書く。
書き方の約束（判定・差分の種類・深刻度・対応の書き方）は [ひな形](../00-template/features.md) を参照。

- **調査時点:** 2026-09-30
  - 旧: `learningware-kiracari`
  - 新: `school-launcher` の `feat/lw2-billing-schema`（`hanataba_dev` とアプリのコードは同じ）
- **根拠の場所の書き方:**
  - 旧は `learningware-kiracari/application/` からの相対パス。
  - 新は `btoc-backend/internal/` / `btoc-frontend/src/` からのパス。
- **この区分はデータを移さない。** 参照データの表は、次の3つを確かめるための形にしている
  - **不要なデータを移していないか**（「移行」が「移す」なのに、新で使わないもの）
  - **新に受け皿のテーブルがあるのに、対象外にしていないか**（「新の受け皿」がある行）
  - **新に同等の機能があるのに、対象外にしていないか**（「新の同等の機能」が ◯ / △ の行）
- 「ステージング」は 2026-09-30 に `tenant_id = 10`（共有講座 0 を含む）で数えた件数
- 旧のメニューは、テナントごとの機能の表（`function_default_*` / `function_admin_*`）で出し分けていた。`application_config` のフラグで止まるのはバッジ（`badge_chk`）だけ

> **要点。** 「使っていないから移さない」とした機能のうち、**外部研修の申請・承認**（F01）と**模試**（F02）は、旧のコードが動く状態で残っていた。
> ステージングでは件数が少ない（外部研修9件）か数えていない（模試）ので、**本番で使っていれば前提が崩れる**（内訳の「本番ダンプで件数を取り直すこと」と同じ）。
> タイピング（F03）と運営スケジュール（F05）は、旧でもすでに止まっていた。

## 3つの確認の結果

| 確認 | 当たったもの | 対応 |
|---|---|---|
| 不要なデータを移していないか | **会場の ID**（F01）。会場の表を移さないのに、ライブの `settings` に `facility_id` だけを残していた | 2026-09-30 に直した（会場の名前・住所・アクセスも文字列で残す） |
| 新に受け皿のテーブルがあるのに、対象外にしていないか | **外部リンク集**（F04）。新の `library_materials` に URL の資料として入る<br>バッジ（F06）は `digital_badges` があるが、付与の記録の表で、旧の定義（`badge_item`）の受け皿ではない | 外部リンク集: 未決（E64）<br>バッジ: 対象外のまま（決定済み） |
| 新に同等の機能があるのに、対象外にしていないか | **外部リンク集**（F04）。新のライブラリで同じことができる（グループ・属性での絞り込みを除く） | 同上（E64） |
| （あわせて）「使っていない」の前提が崩れていないか | **模試**（F02。模試のテスト3件・判定の設定6件）、**外部研修**（F01。研修9件・受講記録8件） | 未決（E63 / E62） |

### F01 集合研修・外部研修・会場
